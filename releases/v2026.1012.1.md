# Vibgrate CLI 2026.1012.1

_Released 2026-10-12_

This release of the Vibgrate CLI includes several improvements to documentation and functionality, particularly around reporting and dependency scanning. Notable changes enhance error handling, output formatting, and the handling of optional fields in lockfiles.

## What changed

### Improved

- The CLI docs now explain how to save a drift baseline, gate a build on it, and which exit code that gate uses.
- Lockfile reads keep the dependency graph and SBOM rows when a lockfile adds an optional field this version does not recognize, with warnings printed for each file and field name.
- vg scan --vulns now checks transitive dependencies in npm, pnpm, and yarn projects, allowing for more comprehensive vulnerability reporting.
- vg build and vg scan do not follow symlinks, preventing potential hangs during the walk.
- vg lib docs now clarify which lockfiles supply the version label and the implications of missing pins.
- vg report --format html includes a Fix available only checkbox, allowing users to filter findings based on fix availability.
- The CLI docs now describe vg serve --http, detailing its configuration and behavior.
- vg fix docs now explain how to preview a plan before applying it, improving user understanding of the command.

### Changed

- vg report --format html writes a self-contained HTML page from the local scan artifact, including severity counts and links to full finding tables.

### Fixed

- vg report --format rejects an unknown value with a usage error that names the value and lists the accepted formats.
- vg scan --format sarif now sets partialFingerprints on every result, ensuring consistent alert identification across runs.
- vg scan JSON and SARIF output now use paths relative to the project, ensuring consistent output across different environments.
- vg evidence release now stops when an SPDX or CycloneDX SBOM is truncated or not valid, providing clearer error messages.
- vg build and vg scan now print one stderr line when many files fail for the same reason, summarizing the issue.
- vg build now resolves workspace packages that share a bare name in a fixed order, ensuring consistent dependency resolution.
- vg scan reports an unresolved license once for the same package version and source path, reducing duplicate entries.
- vg scan now says when paths were left out of the results, providing clearer feedback on the scan process.
- Stopping vg while it writes a graph or report keeps the previous copy, ensuring no data loss.

### Security

- Error text that includes a URL now hides credential query parameters when the parameter name is percent-encoded.
